# 教師保留對學生與 agent 而言就是已借

狀態：proposed。

教師可以先擋下某個可借格（教師保留），讓課堂上「指定的那一格沒空」每次都重現得出來，不必靠同學搶格子或教師用學生身分先訂。學生與 agent 看到的保留格就是已借：查可借時標為已借、預約者顯示名稱為教師填的名字（例如「熱舞社」，沒填就是「保留」），預約時回 `SLOT_TAKEN`。只有教師在月曆監看上分得出保留與學生預約。

保留不是預約：不算進任何學生的預約上限，不能貼海報。重置堂課時保留留著（它跟可借清單一樣是教師為這堂課做的準備），預約與海報清掉。已借的格不能設保留（409 `CONFLICT`），解除保留隨時可以。可借清單整批覆寫時，保留不擋覆寫：被拿掉的格子連同保留一起消失。

## Considered Options

- **第三種狀態「保留」給學生端看見**：放棄。agent 要多懂一個狀態，課堂上「沒空就告知」的情境也會變成要分辨兩種沒空。
- **教師用自己的學生身分先預約**：放棄。教師的個人金鑰不能代表學生（見 0003），且每次重置堂課後都要手動再訂。
- **只靠同學互搶到滿**：放棄。無法保證示範時那一格一定沒空。

## Consequences

- 學生端介面與 OpenAPI 不新增狀態；agent 提示詞不用改。
- 教師端（月曆監看、日展開）要能區分保留與預約，並提供設定／解除保留。
